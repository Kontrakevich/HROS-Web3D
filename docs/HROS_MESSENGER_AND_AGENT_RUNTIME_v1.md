# HROS Messenger & GPT Agent Runtime v1

Дата канонизации: 2026-07-30  
Продуктовая версия: **1.2.0**  
Статус: обязательный интерфейсный и агентный контракт

## 1. Решение

ИИ-дневник и GPT-агенты работают внутри отдельного полноэкранного мессенджера HROS.

Интерфейс использует знакомую модель современного мессенджера:

```text
Список бесед
→ выбранный чат
→ сообщения
→ поле ввода
→ сведения об агенте и использованной памяти
```

HROS не копирует бренд, графику, исходный код или товарные знаки Telegram. Используются общие UX-паттерны: полноэкранная рабочая область, список диалогов, пузырьки сообщений, статусы доставки, поиск, ответ, редактирование, удаление, вложения и информационная панель.

## 2. Полноэкранный интерфейс

При открытии раздела `Дневник` интерфейс COMMAND скрывается под полноэкранным слоем Messenger.

### Desktop

```text
┌─────────────────┬─────────────────────────────┬──────────────────┐
│ Беседы          │ Активный чат                │ Агент и память   │
│ поиск           │ заголовок                   │ статус runtime   │
│ папки           │ сообщения                   │ правила          │
│ список чатов    │ composer                    │ источники HROS   │
└─────────────────┴─────────────────────────────┴──────────────────┘
```

### Mobile

- один активный экран;
- возврат к списку бесед;
- нижний composer с safe-area;
- отсутствие горизонтальной прокрутки;
- полная работоспособность от 320 CSS px.

## 3. Функции мессенджера

Рабочая версия включает:

- отдельные чаты;
- поиск по названиям и сообщениям;
- закрепление и отключение уведомлений;
- сообщения пользователя и агента;
- время и статус доставки;
- ответ на сообщение;
- редактирование собственных сообщений;
- удаление сообщений;
- копирование текста;
- локальные метаданные вложений;
- автоматическое увеличение поля ввода;
- отправку Enter и перенос Shift+Enter;
- индикатор набора ответа;
- список использованных источников HROS;
- экспорт беседы в JSON;
- перевод беседы в проверяемый Diary Change Set.

## 4. GPT-агенты

В системе определены пять специализированных агентов.

### ИИ-дневник

Основной интерфейс свободного рассказа. Отделяет действия и факты от интерпретаций, задаёт один уточняющий вопрос и готовит материал для Change Set.

### Аналитик отношений

Разделяет:

- наблюдаемые факты;
- перспективу пользователя;
- подтверждённую перспективу другого участника;
- неизвестную перспективу;
- гипотезу;
- вопрос для проверки.

### Хранитель памяти

Ищет, сопоставляет и показывает записи HROS с источником, статусом и confidence.

### Навигатор HROS

Помогает выбрать следующий раздел, человека, момент, путь или действие.

### Агент аватара

Предлагает обратимые изменения роли и оболочки аватара. Отношения могут влиять на контекст и ауру, но не на ценность или идентичность человека.

## 5. HROS Memory Gateway

Агент не получает весь snapshot без фильтрации.

```text
Сообщение пользователя
→ токенизация запроса
→ поиск по People / Relationships / Moments / Records
→ фильтр приватности и владельца перспективы
→ ранжирование по совпадению, типу, статусу и confidence
→ ограниченный Context Envelope
→ GPT Agent
→ ответ с [HROS:record-id]
```

### Приоритет памяти

1. Original Memory;
2. Living Memory;
3. Semantic Memory;
4. подтверждённые принципы, факты и перспективы;
5. состояния отношений и грани личности;
6. моменты, люди и связи;
7. наблюдения;
8. гипотезы только с явной маркировкой.

### Приватность

Приватная запись с владельцем перспективы другого человека не передаётся агенту владельца HROS. Совместные и опубликованные записи доступны согласно visibility.

## 6. Агентный runtime

Backend использует OpenAI Agents SDK и Responses API для прямого OpenAI-подключения. Для OpenRouter поддерживается OpenAI-compatible Chat Completions adapter.

Официальные источники:

- https://openai.github.io/openai-agents-python/
- https://openai.github.io/openai-agents-python/models/
- https://openai.github.io/openai-agents-python/sessions/
- https://openai.github.io/openai-agents-python/running_agents/

Зафиксированные зависимости:

```text
openai==2.46.0
openai-agents==0.18.3
```

### OpenAI

```text
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5.4-mini
```

`OPENAI_MODEL` можно заменить моделью, доступной аккаунту. Для повышенного качества модель задаётся конфигурацией сервера, а не жёстко в интерфейсе.

### OpenRouter

```text
OPENROUTER_API_KEY=...
OPENROUTER_MODEL=openai/gpt-5.4-mini
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
```

## 7. API

### GET `/api/v1/agents`

Возвращает:

- список агентов;
- статус подключения;
- provider;
- model;
- признак read-only memory;
- необходимость подтверждения записи.

### POST `/api/v1/agents/chat`

Вход:

```json
{
  "agentId": "relationship",
  "conversationId": "thread-...",
  "message": "Разбери последний разговор",
  "history": [
    {"role": "user", "text": "..."},
    {"role": "assistant", "text": "..."}
  ],
  "memoryLimit": 18
}
```

Выход:

```json
{
  "conversationId": "thread-...",
  "agentId": "relationship",
  "reply": "... [HROS:record-id]",
  "memoryRefs": [],
  "runtime": {},
  "writeApplied": false,
  "confirmationRequired": true
}
```

## 8. Неприкосновенные правила

1. Агент читает память HROS, но не изменяет её автоматически.
2. Сообщение чата не становится фактом только потому, что его обработал GPT.
3. Другому человеку нельзя приписывать отсутствующую перспективу.
4. Каждый персональный вывод должен иметь HROS source reference или маркироваться как новая гипотеза.
5. Агент не оценивает человеческую ценность, качество партнёра или силу любви одной цифрой.
6. Перевод чата в основную память проходит через Diary Change Set.
7. Пользователь может исправить или отклонить каждый proposed change.
8. API-ключ не хранится во frontend или LocalStorage.
9. GitHub Pages работает в локальном Memory Gateway mode и честно показывает, что GPT не подключён.
10. GPT runtime работает только через защищённый backend.

## 9. Локальный режим

При отсутствии backend или API-ключа мессенджер остаётся рабочим:

- хранит беседы локально;
- ищет подтверждённую память HROS;
- показывает источники;
- задаёт безопасные типовые вопросы;
- формирует Diary Change Set.

Локальный режим не маркируется как GPT и не имитирует модельный ответ.

## 10. Критерии готовности

- `Дневник` открывается на весь экран;
- интерфейс содержит список бесед, активный чат и context panel;
- мобильный интерфейс не имеет горизонтального overflow;
- пользователь отправляет сообщение и получает локальный или GPT-ответ;
- ответ показывает использованные HROS records;
- API-ключ отсутствует в клиентском коде;
- агентный runtime сообщает provider и model;
- беседа переводится в Change Set;
- snapshot не изменяется до явного подтверждения;
- Chromium и WebKit проходят acceptance test;
- backend catalog работает без API-ключа;
- chat endpoint без API-ключа возвращает контролируемый `503`;
- production build и GitHub Pages deploy проходят успешно.
