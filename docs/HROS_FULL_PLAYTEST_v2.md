# HROS COMMAND — Full Living World Playtest v2

Дата: 2026-07-31  
Статус: тестовая продуктовая сборка поверх канонического HROS v1  
Базовый контракт: `docs/HROS_UI_UX_GAME_DESIGN_v1.md`

## 1. Цель

Full Playtest v2 делает тестовую версию HROS достаточно полной для проверки не отдельного экрана, а связного пользовательского цикла:

```text
Открыть HROS
→ понять, что делать сейчас
→ быстро сохранить мысль
→ разобрать входящие
→ передать запись в ИИ-дневник
→ проверить Change Set
→ подтвердить изменения
→ увидеть человека, отношения, момент и источник в Living World
→ проверить влияние подтверждённых данных на аватар, путь и хронику
→ оставить структурированный отзыв
```

## 2. Что добавлено

### 2.1. Расширенный экран «Сегодня»

- быстрый захват мысли;
- локальные входящие;
- индикаторы состояния данных;
- отношения с последними подтверждёнными моментами;
- переход в расширенный Living World;
- встроенный сценарий тестирования.

### 2.2. Quick Capture и Inbox

Quick Capture не пишет данные напрямую в `hros.snapshot.v1`.

Каждая запись сначала получает состояние локального черновика:

```text
quick_capture
→ inbox draft
→ ручная правка
→ передача в форму ИИ-дневника
→ обычный Diary Session
→ Change Set
→ подтверждение
→ commit
```

Пользователь может:

- изменить тип записи;
- отредактировать текст;
- удалить черновик;
- передать его в дневник;
- отказаться от передачи.

## 3. Living World v2

Добавлен полноценный 2D-режим исследования мира:

- области жизни;
- люди внутри областей;
- фильтр по области;
- поиск человека;
- карточка выбранного человека;
- значение связи;
- последние моменты;
- перспективы;
- действия;
- переход к Source Inspector;
- отдельная кнопка перехода в Web3D.

Области жизни:

- семья и близкие;
- работа;
- проекты и творчество;
- память и наследие;
- личное пространство;
- здоровье.

Living World не заменяет точные редакторы и не создаёт выводы самостоятельно.

## 4. Source Inspector

Любая доступная запись может быть открыта в инспекторе основания.

Инспектор показывает:

- entity type;
- record kind;
- statement или meaning;
- ID;
- status;
- confidence;
- visibility;
- version;
- source label;
- source kind;
- дату обновления;
- связанные ID.

Это обязательный мост между игровым интерфейсом и проверяемой моделью HROS.

## 5. Аватар

В редактор добавлены предложения, полученные из уже существующих записей HROS.

Поддерживаемые тестовые предложения:

- AI-орбита;
- спортивный модуль;
- семейный символ;
- архитектурная сетка.

Каждое предложение показывает связанные источники. Нажатие «Примерить» только включает локальный UI-модификатор. Оно не изменяет Identity Core и не создаёт domain record.

## 6. Пути

Экран путей дополнен списком оснований прогресса.

Пользователь может открыть любой источник и увидеть:

- вид записи;
- формулировку;
- статус;
- confidence;
- provenance.

Прогресс остаётся count-based интерфейсным индикатором и не является оценкой личности.

## 7. Хроника

Добавлены:

- поиск;
- фильтр по участнику;
- фильтр по статусу;
- экспорт хроники;
- сохранение принципа: гипотеза не становится сюжетным фактом.

## 8. Система и данные

В Build Mode добавлены безопасные локальные операции:

- экспорт полного snapshot;
- разбор входящих;
- заполнение playtest-отзыва;
- сброс только тестовых UI-настроек;
- сохранение основной модели HROS при сбросе playtest.

## 9. Playtest Feedback

Форма оценивает:

- понятность навигации;
- понятность главного действия;
- доверие к данным и подтверждениям;
- ощущение живого игрового мира;
- основные затруднения;
- недостающие функции;
- элементы, которые нужно сохранить.

Отзыв хранится локально и экспортируется в JSON.

## 10. Локальные ключи

```text
hros.command.full.v2
hros.command.inbox.v2
hros.command.feedback.v2
```

Они отделены от:

```text
hros.snapshot.v1
```

Удаление или сброс Full Playtest не должен удалять подтверждённые данные HROS.

## 11. Ограничения

В v2 всё ещё не входят:

- server-side Inbox API;
- отдельная Avatar Ontology;
- Avatar Change Set;
- GLB/VRM-персонаж;
- LLM extraction provider;
- multiplayer couple world;
- серверное хранение отзывов;
- автоматический импорт календаря, почты или мессенджеров.

## 12. Критерии приёмки

1. Full Playtest загружается после HROS COMMAND.
2. На экране «Сегодня» доступны Quick Capture, Inbox и Relationship Pulse.
3. Quick Capture не изменяет `hros.snapshot.v1`.
4. Inbox позволяет редактировать и удалять запись.
5. Передача в дневник не отправляет сообщение автоматически.
6. World v2 показывает области, людей и detail panel.
7. Source Inspector открывает source/status/confidence/version.
8. Avatar Suggestion не изменяет domain snapshot.
9. Chronicle filters не изменяют данные.
10. Export работает локально.
11. Сброс playtest не удаляет domain snapshot.
12. Chromium и WebKit проходят browser acceptance без console errors.
