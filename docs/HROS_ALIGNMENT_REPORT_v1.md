# HROS v1 — Alignment Report

Дата проверки: 2026-07-30

## Результат

Архитектурные и продуктовые противоречия между прототипом v0.4 и первоначальной задумкой устранены в HROS v1. Существующий код Person/Relationship/Moment не выброшен: он мигрирован в более широкую онтологию и больше не считается полной моделью HROS сам по себе.

## Исправленные несоответствия

### 1. Отсутствовал единый Blueprint

**Было:** разработка шла слоями v0.2–v0.4 без актуального канонического документа.

**Исправлено:** Blueprint, Product Principles, Domain Ontology, Data Lifecycle, Privacy, Skill Architecture, Visual Semantics, Migration и Acceptance Criteria являются обязательными версионируемыми контрактами CI.

### 2. Версии продукта расходились

**Было:** UI, LocalStorage, README и backend одновременно ссылались на v0.2, v0.3 и v0.4.

**Исправлено:** package, UI, API, meta, schema, storage, diagnostics, history и tests используют `1.0.0`; старая запись мигрируется из `hros.snapshot.v0.2` без удаления исходного ключа.

### 3. HROS сводилась к людям, связям и моментам

**Было:** отсутствовал полноценный контур знания.

**Исправлено:** добавлены Evidence, Fact, Perspective, Action, Person Facet, Relationship State, Observation, Hypothesis, Verification, Pattern, Principle, Memory, Interview, Book и Consent records.

### 4. Факт смешивался с интерпретацией

**Было:** description/meaning/confidence находились внутри одной записи момента.

**Исправлено:** DomainRecord отделяет тип знания, владельца перспективы, source, evidence, supports/contradicts, confidence, status и visibility. Perspective требует владельца; Hypothesis остаётся отдельным типом.

### 5. Не поддерживались разные перспективы

**Было:** у момента была одна агрегированная оценка отношений.

**Исправлено:** разные Perspective могут сосуществовать. Отсутствующая перспектива Снежи явно хранится как неизвестная draft-запись и не заполняется догадкой системы.

### 6. Person была карточкой, а отношения — одной «силой»

**Было:** имя, роль, тип, strength и summary.

**Исправлено:** изменяемые свойства личности представлены `person_facet`; динамика отношений — `relationship_state` с близостью, доверием, безопасностью, взаимностью, доступностью, уважением границ и напряжением по периодам и перспективам.

### 7. Не было причинной модели взаимодействия

**Было:** только Moment и общий relationshipEffect.

**Исправлено:** Action хранит действующего, получателей, наблюдаемое поведение, заявленное намерение, затронутые потребности/границы и варианты восстановления. Восприятия и реакции остаются отдельными Perspective.

### 8. Не были реализованы три уровня памяти

**Исправлено:** Original Memory сохраняет исходник, Semantic Memory — структуру, Living Memory — актуальное понимание с confidence, основаниями и датой проверки.

### 9. Не было режима пары

**Исправлено:** интерфейс разделяет private-пространство Михаила, private-пространство Снежи и совместную область. Новая запись по умолчанию private.

### 10. Не было книги отношений

**Исправлено:** Book Chapter, Principle и Narrative Fragment отображаются с provenance и областью действия.

### 11. Web3D оставалась декоративной

**Исправлено:** дистанция кодирует близость выбранной перспективы, размер — значимость, прозрачность — уверенность, пунктир — спорный/гипотетический статус, цвет связи — доверие/напряжение, стрелка — направление действия. В интерфейсе присутствует легенда.

### 12. Skill-архитектура была частичной

**Исправлено:** добавлены registry, универсальные JSON Schemas и контракты Person Profile, Relationship State, Moment Engine, Action Impact, Evidence Intake, Perspective Capture, Interview Engine, Memory Projection, Book Builder, Consent/Visibility, n8n Adapter и Diagnostic Package.

### 13. Privacy не была частью домена

**Исправлено:** visibility и consent policy входят в запись; CORS больше не равен `*`; Docker не содержит фиксированного пароля, а START_HROS создаёт локальный случайный secret автоматически.

### 14. Сборка считалась доказательством работы

**Исправлено:** deploy блокируется backend-тестами и реальными сценариями Chromium/WebKit: миграция, редактирование момента, создание Perspective, Couple Mode, Book и отсутствие console errors.

## Оставшиеся несоответствия

После Alignment Release не осталось известных противоречий в архитектуре, модели данных и демонстрационном интерфейсе. Остались следующие **не реализованные production-возможности**, которые не следует выдавать за готовые:

1. Реальная многопользовательская аутентификация, server-side authorization, tenant isolation, шифрование и аудит доступа.
2. Приглашение второго участника пары и реальный процесс выдачи/отзыва согласия между аккаунтами.
3. Автономное AI-интервью: сейчас реализованы ontology, UI session record и skill contract, но не подключена LLM-оркестрация.
4. Автоматическое извлечение наблюдений, проверка гипотез, поиск паттернов и синтез принципов: контракты и хранилище готовы, агентные workflow ещё не развёрнуты.
5. Готовые n8n workflow: формат и adapter contract готовы, импортируемые/авторазворачиваемые workflow будут отдельной поставкой.
6. Защищённое файловое/object storage для фотографий, голоса, переписки и документов; GitHub Pages сохраняет только метаданные и ссылки.
7. Специализированные редакторы каждой сущности: сейчас все DomainRecord доступны через универсальный редактор, но отдельные UX для Person Facet, Relationship State, Verification и Consent ещё предстоят.
8. Полноценный timeline и воспроизведение исторической динамики Web3D; семантика данных уже применена к текущему состоянию.

## Вывод

HROS v1 снова соответствует первоначальному замыслу на уровне Blueprint, ontology, data lifecycle, privacy, skill contracts, Repository Service, API, Web3D semantics и работающего демонстрационного интерфейса. Следующая разработка должна расширять production-возможности внутри этих контрактов, а не менять фундамент продукта.
