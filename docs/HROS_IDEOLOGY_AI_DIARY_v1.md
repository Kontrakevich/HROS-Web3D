# HROS v1 — Идеология, источники данных и перспективы

Дата канонизации: 2026-07-30  
Статус: обязательный продуктовый контракт

## 1. Определение

**HROS — живая операционная система человеческих отношений, которая превращает добровольный диалог человека с ИИ-дневником в проверяемую, редактируемую и развивающуюся карту людей, отношений, моментов, перспектив и взаимного влияния.**

HROS не является обычным дневником, CRM, системой оценки людей или психологическим диагнозом. Дневник — основной интерфейс ввода; граф, карточки, связи и выводы — производные представления подтверждённых данных.

Центральный принцип:

> Давай мы оба будем понимать, как наши действия влияют друг на друга и к чему это приводит.

## 2. Основная идеология

HROS помогает человеку:

- сохранить прожитое без подмены исходного материала выводами;
- различать наблюдаемые события, личные переживания и гипотезы;
- видеть динамику отношений во времени;
- понимать последствия действий для участников отношений;
- замечать повторяющиеся сценарии;
- проверять собственные интерпретации;
- выбирать дальнейшие действия осознанно;
- сохранять личную, парную и семейную память.

Система не определяет, кто «прав», не назначает мотивы другим людям и не превращает AI-интерпретацию в факт.

## 3. Первичный источник данных

### 3.1. Основной канал

**Живой диалог с ИИ-дневником является основным источником информации для анализа и построения связей.**

Пользователь рассказывает о жизни естественным языком. ИИ-дневник:

1. задаёт один уточняющий вопрос за шаг;
2. сохраняет ответ дословно;
3. отделяет факт от перспективы;
4. выделяет участников, действия, моменты и последствия;
5. предлагает наблюдения и гипотезы;
6. формирует черновой Change Set;
7. показывает его пользователю;
8. вносит только явно подтверждённые изменения.

### 3.2. Дополнительные источники

- ручное создание и редактирование;
- голосовая расшифровка;
- переписка;
- фотографии и видео;
- документы;
- календарные события;
- ссылки и метаданные.

Импортированные источники не получают более высокий статус автоматически.

## 4. Базовые принципы

### 4.1. Диалог первичен, граф вторичен

Web3D, карточки людей и показатели отношений строятся из подтверждённых записей. Они не являются первичными источниками истины.

### 4.2. Пользователь владеет смыслом

ИИ предлагает структуру и гипотезы. Пользователь исправляет, принимает или отклоняет их.

### 4.3. Никаких скрытых изменений

Во время сессии основная модель не изменяется. Все предложения остаются в отдельном Change Set до явного подтверждения.

### 4.4. Исходная память неизменяема

Original Memory сохраняет транскрипт, исходное сообщение или файл. Semantic и Living Memory не заменяют исходник.

### 4.5. Факт, перспектива и гипотеза разделены

- Fact — проверяемое утверждение.
- Perspective — переживание или смысл конкретного человека.
- Observation — осторожное описание признака.
- Hypothesis — проверяемое предположение.
- Verification — результат проверки.

### 4.6. Перспективы не смешиваются

Версия Михаила, версия Снежи, совместно подтверждённая часть и AI-гипотеза существуют отдельно.

### 4.7. Отношение — динамическая система

Отношение хранит историю близости, доверия, безопасности, взаимности, доступности, напряжения и уважения границ по периодам и перспективам.

### 4.8. Момент — минимальная единица изменения

Момент связывает контекст, участников, действие, переживание, интерпретацию, последствия и значение.

### 4.9. Приватность по умолчанию

Новая запись создаётся как `private`. ИИ не повышает видимость самостоятельно.

### 4.10. Любой вывод ведёт к источнику

Гипотеза должна открываться через supporting evidence до конкретной реплики диалога.

### 4.11. История не переписывается

Новая интерпретация создаёт новую версию. Старое понимание сохраняется с датой и источником.

## 5. Контракт сессии ИИ-дневника

```text
active
→ analyzing
→ review
→ awaiting_confirmation
→ committed
```

Допустимые завершения:

```text
saved_as_draft | rejected | cancelled
```

Структура:

```text
DiarySession
├── DiaryMessages
├── OriginalTranscript
├── ExtractedEvidence
├── ProposedChanges
├── ManualCorrections
├── ChangeSet
├── UserConfirmation
└── CommitResult
```

В конце сессии пользователь получает список:

- что будет добавлено;
- что будет обновлено;
- какие гипотезы предложены;
- на каких репликах они основаны;
- какая видимость установлена;
- какие изменения отклонены.

Без подтверждения `UserConfirmation` данные не переходят в основную модель HROS.

## 6. Три уровня памяти

### Original Memory

Дословная и версионируемая запись источника.

### Semantic Memory

Структурированные люди, отношения, моменты, факты, перспективы и связи.

### Living Memory

Текущее понимание с `confidence`, `derivedFrom`, `validFrom` и датой следующей проверки.

## 7. Перспективы развития

### Ближний горизонт

- полноценная LLM-оркестрация ИИ-дневника;
- автоматическое извлечение сущностей и связей;
- управляемые Change Set;
- источник до конкретной реплики;
- подтверждение в конце каждой сессии;
- специализированные редакторы;
- timeline динамики отношений.

### Режим пары

- личное пространство каждого;
- совместно подтверждённое пространство;
- отображение совпадений и расхождений;
- выдача и отзыв согласия;
- отсутствие доступа к private-записям партнёра.

### Семейная память

- истории поколений;
- голосовые воспоминания;
- семейные принципы;
- документы и фотографии;
- преемственность и жизненные периоды.

### Книга отношений

Подтверждённые истории, перспективы, паттерны и принципы собираются в живую книгу с provenance и версиями понимания.

### Ассистент осознанного действия

Перед разговором HROS сможет показать факты, неизвестные перспективы, прошлые триггеры, затронутые потребности и возможные восстановительные действия.

## 8. Аудит реализованной версии

| Область | Состояние до корректировки | Коррекция |
|---|---|---|
| ИИ-дневник как основной вход | Не был главным пользовательским сценарием | Добавлен отдельный первичный раздел |
| Дословный транскрипт | Онтология была, рабочего цикла не было | Сессия сохраняет Original Memory после подтверждения |
| Change Set | Отсутствовал | Добавлен review с включением, редактированием и отклонением |
| Подтверждение в конце | Статусы существовали без процедуры | Добавлена явная confirmation-запись |
| Изменения до подтверждения | Ручные формы сохраняли сразу | Дневниковый контур изолирован до commit |
| Разделение уровней знания | Было в DomainRecord | Сохранено и применено к diary records |
| AI-анализ | Только skill contract | В сборке честно обозначен guided mode; LLM не имитируется |
| Транзакционность API | Не реализована | LocalStorage commit атомарный; server-side batch endpoint остаётся production-задачей |

## 9. Ограничение текущей сборки

Текущая версия реализует безопасный пользовательский цикл:

```text
диалог → черновик → review → подтверждение → записи HROS
```

Автоматическая LLM-классификация и извлечение связей пока не подключены. Локальный интерфейс не выдаёт эвристику за интеллектуальный анализ. Подключение выполняется через `ai-diary-session` и `interview-engine` skills.
